УДК 004.89

ИНТЕЛЛЕКТУАЛЬНЫЙ АГЕНТ ПОДБОРА ГИТАР НА ОСНОВЕ ОБРАБОТКИ ЕСТЕСТВЕННОГО ЯЗЫКА И МНОГОКРИТЕРИАЛЬНОГО РАНЖИРОВАНИЯ

Ключевые слова: рекомендательная система, большая языковая модель, обработка естественного языка, многокритериальное ранжирование, подбор гитар

Поисковые интерфейсы музыкальных маркетплейсов оперируют техническими параметрами (тип звукоснимателей, порода дерева, бренд), тогда как пользователи описывают желаемый инструмент субъективными эпитетами («тёплый звук», «яркий тембр», «агрессивное звучание»), что формирует семантический разрыв между намерением и системой поиска. В отличие от стандартных фильтров маркетплейсов, требующих явного задания технических характеристик, интеллектуальный агент принимает естественно-языковое описание и преобразует его в структурированный поисковый план. Цель настоящей работы — разработка такого агента для подбора гитар на маркетплейсе Reverb с последующим ранжированием результатов по степени соответствия исходному запросу. Входными данными системы являются текстовый запрос пользователя, а выходными — список найденных объявлений, упорядоченный по рассчитанной релевантности.

Предлагаемое решение использует большую языковую модель Llama 3.3 70B [2], построенную на архитектуре Transformer [1], в качестве ядра семантического анализа. На уровне пользовательского взаимодействия агент поддерживает сценарии поиска и консультации, а во внутреннем контуре маршрутизации выделяет три класса намерений: поиск, консультация и нерелевантный запрос. Семантическая маршрутизация выполняется LLM-маршрутизатором, который возвращает формализованный JSON-план обработки: тип намерения, признак достаточности данных для поиска, список недостающих полей и нормализованные поисковые параметры. Такой контракт отделяет вероятностный этап интерпретации естественного языка от детерминированных этапов проверки данных, обращения к источнику объявлений и ранжирования. В режиме поиска модель извлекает из свободного текста тип инструмента, ценовой диапазон, звукосниматели, бренд и признаки желаемого звучания, опираясь на предметную таблицу маппинга абстрактных звуковых характеристик в технические спецификации. Например, характеристика «тёплый звук» нормализуется как внутренний признак тёплого звучания и используется при формировании поисковых запросов, выборе релевантных конфигураций звукоснимателей и последующем ранжировании. В режиме консультации отдельный промпт LLM генерирует экспертный ответ на теоретические вопросы.

Для ранжирования найденных объявлений разработан алгоритм взвешенной многокритериальной оценки [3]. Итоговый балл каждого результата вычисляется как взвешенная сумма оценок по семи критериям: соответствие бюджету, тип инструмента, конфигурация звукоснимателей, бренд, характер звучания, музыкальный стиль и релевантность заголовка. В прототипе используется экспертно заданная конфигурация весов: 0,25; 0,20; 0,15; 0,10; 0,10; 0,10 и 0,10 соответственно. Каждый критерий оценивается по шкале от 0 до 100 баллов с промежуточными градациями. Алгоритм адаптивен: при отсутствии дополнительных параметров инструмента формула автоматически упрощается до двух критериев — бюджет и релевантность заголовка с весами 0,55 и 0,45, — что позволяет сохранить ранжирование при минимальном наборе извлечённых параметров.

Система реализована в клиент-серверной архитектуре. Серверная часть включает модули семантической маршрутизации, обращения к Reverb API или локальному демонстрационному набору объявлений, многокритериального ранжирования и хранения истории диалога; клиентская часть предоставляет интерфейс взаимодействия с агентом. Последовательность обработки запроса включает семантическую маршрутизацию и извлечение параметров в едином LLM-вызове, валидацию структурированного плана, уточнение недостающих данных или обращение к источнику объявлений, ранжирование и выдачу топ-5 результатов пользователю. Для снижения недетерминированности LLM серверная часть проверяет JSON-контракт и допустимые значения полей; при некорректном ответе модели система возвращает явную ошибку обработки, а не использует эвристическое распознавание естественного языка.

Разработан и протестирован рабочий прототип системы [4]. Работоспособность прототипа проверена на наборе сценариев, покрывающих поиск по бюджету, модели и характеру звучания, консультационные вопросы, уточняющие реплики и нерелевантные запросы. LLM-маршрутизатор использует предметный маппинг из 23 абстрактных описаний звучания и жанровых признаков для формирования структурированных параметров поиска; серверная часть валидирует полученный план и возвращает ранжированные результаты. Для воспроизводимой демонстрации поддерживается режим работы с локальным набором данных, сохраняющий полный конвейер фильтрации и ранжирования. Проверка охватывает модульные, интеграционные и сквозные сценарии обработки пользовательского запроса.

К ограничениям текущей версии относятся: поддержка единственного маркетплейса (Reverb); ограниченный набор нормализуемых признаков инструмента и звучания; зависимость качества маршрутизации и извлечения параметров от возможностей используемой языковой модели; необходимость строгой валидации структурированных ответов LLM; отсутствие механизма персонализации на основе истории предпочтений пользователя. Перспективные направления развития включают расширение на другие торговые площадки, увеличение предметной базы маппингов, введение количественных метрик качества маршрутизации и внедрение пользовательских профилей.
